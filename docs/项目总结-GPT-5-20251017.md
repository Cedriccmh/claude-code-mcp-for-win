## 项目概览

Claude Code MCP Server 是一个基于 MCP（Model Context Protocol）的 stdio 服务器，提供统一工具 `claude_code`，使 LLM 能以一键/单次调用的方式驱动 Claude Code CLI，并默认跳过权限确认（`--dangerously-skip-permissions`），以提升在真实项目中的自动化编辑、多步工作流与系统操作能力。

### 核心价值
- **权限无阻塞**：一次性在本机接受权限后，后续通过 MCP 工具直接使用 `--dangerously-skip-permissions`，无人工打断。
- **上下文更省**：通过统一工具队列命令，减少冗余对话与上下文占用。
- **成本友好**：将文件操作、Git 等常规任务下放到 Claude Code CLI，重型推理交由更合适的模型。
- **系统可达性强**：当本地 IDE/代理受限时，转而让 Claude Code 执行更底层的文件/命令操作。

## 架构与实现
- **语言与依赖**：TypeScript（`type: module`），核心依赖 `@modelcontextprotocol/sdk`，测试用 `vitest`。
- **入口**：`dist/server.js`（生产运行）与 `src/server.ts`（开发调试）。NPM bin 名称 `claude-code-mcp`。
- **MCP 服务**：使用 `StdioServerTransport` 暴露一个工具 `claude_code`。
- **CLI 发现机制**（`findClaudeCli`）：
  - 优先读取 `CLAUDE_CLI_NAME`：
    - 绝对路径：直接使用；
    - 简单可执行名：后续走 PATH 查找；
    - 相对路径（含 `./`、`../` 或包含 `/`）：拒绝（安全与可移植性考虑）。
  - 若未指定或未命中，本地优先尝试 `~/.claude/local/claude`；否则回退到 `claude` 并依赖 PATH。
- **进程执行**（`spawnAsync`）：`shell: false`，收集 stdout/stderr，默认超时 30 分钟（1_800_000ms）。
- **CWD 策略**：
  - 默认工作目录为当前用户的 HOME；
  - 如 `workFolder`（绝对路径）有效则使用；
  - 不存在则回退到默认并记录告警。
- **一次性版本打印**：首次调用时向 stderr 打印 `claude_code v<版本> started at <ISO 时间>` 便于定位与排错。

## 工具接口（MCP）
- **名称**：`claude_code`
- **输入**：
  - `prompt`（string，必填）：要交由 Claude Code 执行的自然语言指令；
  - `workFolder`（string，选填）：执行时的工作目录，建议提供绝对路径以获得稳定文件/仓库上下文。
- **输出**：以 `text` 形式返回 Claude CLI 的 stdout（stderr 仅用于调试/日志）。

## 环境与配置
- **Node 要求**：v20+（ESM 语义、进程管理与 SDK 兼容性）。
- **主要环境变量**：
  - `CLAUDE_CLI_NAME`：覆盖 Claude CLI 可执行文件名或绝对路径（源码已实现，推荐使用）；
  - `MCP_CLAUDE_DEBUG`：`true` 启用详细调试日志（输出到 stderr）。
- 说明：README 底部曾提到 `CLAUDE_CLI_PATH`，但以源码为准：当前生效的是 `CLAUDE_CLI_NAME` 与 `MCP_CLAUDE_DEBUG`。

## 安装与使用
### 在 MCP 客户端中以 npx 使用（推荐）
在客户端的 `mcp.json`（或等效配置）中加入：

```json
"claude-code-mcp": {
  "command": "npx",
  "args": ["-y", "@steipete/claude-code-mcp@latest"]
}
```

如需自定义 CLI 名称（或切换不同版本），可设置环境变量：

```json
"claude-code-mcp": {
  "command": "npx",
  "args": ["-y", "@steipete/claude-code-mcp@latest"],
  "env": {
    "CLAUDE_CLI_NAME": "claude-custom"
  }
}
```

### 首次权限接受（必做一次）
需先在本机以交互方式运行并接受危险权限跳过：

```bash
npm install -g @anthropic-ai/claude-code
claude --dangerously-skip-permissions
```

完成后，MCP 服务器即可在无交互场景下传递该参数。

### MCP 客户端配置路径（常见）
- Cursor：
  - Windows：`%APPDATA%\Cursor\mcp.json`
  - macOS：`~/.cursor/mcp.json`
  - Linux：`~/.config/cursor/mcp.json`
- Windsurf：
  - Windows：`%APPDATA%\Codeium\windsurf\mcp_config.json`
  - macOS：`~/.codeium/windsurf/mcp_config.json`
  - Linux：`~/.config/.codeium/windsurf/mcp_config.json`

## 本地开发与运行
- 克隆并安装依赖：`npm install`。
- 开发运行：`npm run dev`（`tsx src/server.ts`）。
- 构建：`npm run build`（输出到 `dist/`）。
- 启动脚本：
  - macOS/Linux：`start.sh`（优先运行 `dist/server.js`，否则回退 `tsx src/server.ts`）。
  - Windows：`start.bat`（启动 `dist/server.js`）。

## 测试体系
- 测试框架：Vitest，包含单元与端到端（E2E）测试。
- 命令：
  - 运行全部：`npm test`
  - 仅单测：`npm run test:unit`
  - E2E（含构建）：`npm run test:e2e`
  - 本地集成（需本机安装并登录 Claude CLI）：`npm run test:e2e:local`
  - 监听：`npm run test:watch`
  - 覆盖率：`npm run test:coverage`
- E2E 策略：
  - CI 与大多数自动环境下使用 Mock Claude CLI（创建于临时目录），验证协议交互、CWD 选择、并发处理与错误恢复；
  - 本地可开启真实 CLI 的集成测试（默认跳过）。

## 发布流程
- 参考 `docs/RELEASE_CHECKLIST.md` 与 `RELEASE.md`：
  - 确保测试、构建、类型检查与 Lint 全绿；
  - 同步更新版本：`package.json` 与 `src/server.ts` 的常量 `SERVER_VERSION`；
  - 使用脚本 `scripts/publish-release.sh`：跑测、构建、打 tag、推送、生成 GitHub Release、发布 npm。

## 故障排查（Troubleshooting）
- 找不到命令：
  - `claude-code-mcp`：检查全局安装目录是否在 PATH；npx 可直接使用；
  - `claude`/`~/.claude/local/claude`：确认已安装并可执行。
- 权限问题：未完成首次 `--dangerously-skip-permissions` 接受。
- JSON 解析报错：调试模式 (`MCP_CLAUDE_DEBUG=true`) 会输出 stderr，可能干扰 JSON 渲染；关闭后重试。
- ESM/Import 错误：请使用 Node.js v20+。

## 安全与注意事项
- `CLAUDE_CLI_NAME` 禁止相对路径（`./`、`../` 或包含 `/` 的相对形式），仅允许绝对路径或简单命令名。
- `workFolder` 建议使用绝对路径，避免路径穿越与意外定位。
- 长时任务：默认 30 分钟超时，建议将复杂任务拆分。

## 快速上手清单
1) 安装 Claude CLI 并执行一次 `claude --dangerously-skip-permissions`。
2) 在 MCP 客户端 `mcp.json` 配置 `claude-code-mcp`（推荐用 `npx`）。
3) 可选：设置 `CLAUDE_CLI_NAME` 指定 CLI；必要时开启 `MCP_CLAUDE_DEBUG` 调试。
4) 使用工具 `claude_code`，提供 `prompt` 与（建议）绝对 `workFolder`，开始自动化操作。
